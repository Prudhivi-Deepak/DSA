Step 1

Functional Requirements
-------------------------------------------------------------------------------------
parking lot
Entry Flow
    - we go to the entry gate and generate the ticket fo the slot 
    - park our vechicle at the slot
    - mark teh slot as occupied
    - Return Entry result as SUCCESS/FAILURE status
Exit Flow
    - we checkout the slot --> at the exit gate provide the ticket and mark as empty after payment
    - Now the admin will calculate the fee and provide it
    - pay the fee (processing the payment) -> generate Payment Result SUCCESS/FAILURE
    - SUCCESS -> Return the ExitResult as SUCCESS
    - FAILURE -> Return the ExitResult as FAILURE

Admin configuration
    - manage the building floors and slots in the software
    - Define the pricing rules (flat + hourly charges) based on vechicle type
    - view current parking status

# In any case of server failure Human intervention is needed

Non-Functional Requirements
----------------------------------------------------------------
scalability : Must support multipple floors and slots with 1000's of slots'
consistency : Strong consistency for slot allocation and release
Availability : High availablilty for Entry/Exit Gates even during payment failure
Latency : low latency( <500 ms) for ticket generation and exit processing
Extensibility : easily add new vechicle types ? pricing strategies or gateways
security : Role-based access for admin actions

Edge Cases
----------------------------------------------------------------------------------
payment failure during exit - retry and hold slot
ticket lost - allow admin to check manually
clock skew - system time validation
slot state mismatch - peridic reconciliation
---------------------------------------------------------------------------------
