streams & buffers
consider a big file being uploaded to a server
- if the server tries to read the entire file into memory at once, it can lead to high memory usage and potential crashes
- instead, the server can read the file in smaller chunks using streams
- streams allow data to be processed piece by piece, reducing memory consumption and improving performance
buffer is like a bus stop
 - hold multiple chunks of data temporarily before they are processed/released or sent to their destination


req.on() ==> on allows us to listen to different events like data event /(close, end, error, readable, data events)
    - data event ==> triggered when a new chunk of data is available to read from the stream
    - end event ==> triggered when there is no more data to read from the stream
    - error event ==> triggered when an error occurs while reading from the stream
    - readable event ==> triggered when the stream is ready to be read
    - close event ==> triggered when the stream is closed

It's all about middleware functions
A middleware function is a function that has access to the request object (req), 
                                                    the response object (res), and 
                                                    the next middleware function 
                                    in the application's request-response cycle.
multiple middleware functions can be chained together to handle a request instead of a huge function doing everything

const express = require('express'); //exports a function
const app = express(); //app is a valid request handler
createseerver(app);//pass app to server

app.use() ==> allows us to add new middleware functions to the application
    - it takes a middleware function as an argument
    - the middleware function can perform any task, such as logging, authentication, parsing request bodies, etc.
    - after performing its task, the middleware function can either send a response to the client
         or call the next() function to pass control to the next middleware function in the chain
    -works fine with bothe GET and POST request

//can't rename req, res, next
app.use((req, res, next) => {
    console.log('Middleware 1: Logging request details');
    console.log(`Request Method: ${req.method}, Request URL: ${req.url}`);
    next(); // Pass control to the next middleware function
});

app.use((req, res, next) => {
    console.log('Middleware 2: Authenticating user');
    res.send('Response from send'); // Utility function send response to the client by automatically setting headers and status codes
});

const bodyParser = require('body-parser');
app.use(bodyParser.urlencoded({ extended: false }));

views ==> to store the templates for rendering dynamic HTML content
    - by default, express looks for views in a folder named 'views' in the root directory of the project
    - we can change the default views directory using 
        app.set('views', 'path/to/views')

static content ==> to serve static files like CSS, JS, images, etc.
    - use express.static middleware to serve static files from a specific directory
    - for example, to serve static files from a folder named 'public':
        app.use(express.static(path.join(__dirname, 'public')));
    - now, any file in the 'public' folder can be accessed directly via its URL
        e.g., if there's a file 'public/css/styles.css', it can be accessed at '/css/styles.css'
        in user.html we can use 
            <link rel="stylesheet" href="/css/styles.css">

templating engines ==> to generate dynamic HTML content
    - allows us to create HTML templates with placeholders for dynamic data
    - when rendering the template, the placeholders are replaced with actual data

Pug ==> popular templating engine for Node.js
    - uses indentation-based syntax to define HTML structure
    - allows us to embed JavaScript code within the template to generate dynamic content
To use Pug with Express:
1. Install Pug using npm:
   npm install pug
2. Set Pug as the view engine in your Express app:
   app.set('view engine', 'pug');
3. Create Pug templates in the 'views' directory
4. Use res.render() to render a Pug template and send it as a response:
   res.render('template-name', { data: 'value' });
    - 'template-name' is the name of the Pug template file (without the .pug extension)
    - the second argument is an object containing data to be passed to the template

handlebars ==> another popular templating engine for Node.js
    - uses double curly braces {{}} to denote placeholders for dynamic data
    - allows us to create reusable templates with partials and helpers
To use Handlebars with Express:
1. Install Handlebars using npm:
   npm install express-handlebars@3.0
2. Set Handlebars as the view engine in your Express app:
    const exphbs = require('express-handlebars');
    app.engine('handlebars', exphbs());
    app.set('view engine', 'handlebars');
3. Create Handlebars templates in the 'views' directory
4. Use res.render() to render a Handlebars template and send it as a response:
   res.render('template-name', { data: 'value' });
    - 'template-name' is the name of the Handlebars template file (without the .handlebars extension because we set engine to 'handlebars')
    - the second argument is an object containing data to be passed to the template

{{{ body }}} ==> to render unescaped HTML content in Handlebars
    - by default, Handlebars escapes HTML content to prevent XSS attacks
    - if we want to render raw HTML content, we can use triple curly braces {{{ }}} instead of double curly braces {{ }}
main-layout.hbs ==> to define a common layout for all templates in Handlebars
    - allows us to define a common structure for all pages in the application
    - we can define a header, footer, and other common elements in the main layout
    - individual templates can then be rendered within the main layout using {{{ body }}}


ejs ==> another popular templating engine for Node.js
    - uses <% %> to denote JavaScript code and <%= %> to denote placeholders for dynamic data
    - allows us to embed JavaScript code within the template to generate dynamic content
To use EJS with Express:
1. Install EJS using npm:
   npm install ejs
2. Set EJS as the view engine in your Express app:
   app.set('view engine', 'ejs');
3. Create EJS templates in the 'views' directory
4. Use res.render() to render an EJS template and send it as a response:
   res.render('template-name', { data: 'value' });
    - 'template-name' is the name of the EJS template file (without the .ejs extension)
    - the second argument is an object containing data to be passed to the template
